## Scene intent

The site shell must make EVER immediately recognizable, expose every primary destination without jargon, provide a persistent business action only when that service is verified, and close each page with a calm route back into the site. It succeeds when visitors can identify their current location, reach every valid destination by keyboard or without JavaScript, open and close mobile navigation without losing context, and understand the shell in static desktop and mobile screenshots.

## Composition

Use white as the header canvas, deep navy for primary type and the footer field, and blue as the single dominant accent for links, directional cues, focus, and selected states. Preserve the approved blue, cyan, and lime progression only inside the production `V` asset. Sample every color from approved assets rather than inventing near-matches.

On desktop, use the same 12-column grid and content width as page scenes. The header has one stable height between approximately 72px and 88px. Place the approved wordmark at the upper left, the six primary navigation links in the center or center-right, and the persistent business action at the far right. Use 16px to 18px navigation and control text. Keep the surface white over bright opening scenes. After the page leaves its top position, retain the same height and add a solid white surface and thin divider without animated shrinking. Do not invert the first implementation over navy scenes. A future scene-specific inversion requires a separate approved contract and measured contrast.

Collapse the desktop arrangement when the complete navigation no longer fits with readable spacing, rather than targeting a particular device name. On the collapsed layout, retain the wordmark and one menu toggle in the top row. The same navigation list expands directly below that row in normal document flow, with a maximum height that fits the remaining viewport and vertical scrolling when necessary. Do not duplicate desktop and mobile navigation markup. Primary targets must be 48px to 56px high on mobile.

The footer begins after page content without overlapping a final page action. On desktop, use a deep navy 12-column field with the brand block occupying approximately five columns and a plain navigation grid occupying the remaining seven. The brand block contains the approved wordmark only if a reversed asset is supplied, otherwise it uses the text brand name without recoloring the logo. On mobile, stack the brand block before the navigation list. Keep footer links at 16px or larger, preserve generous vertical spacing, and avoid cards, badges, decorative dashboards, photography, and background circuit wallpaper.

## Motion

- Mobile navigation reveal. Job: transition. Trigger: activation of the mobile menu toggle. Duration: 180ms opening and 120ms closing. Easing: `cubic-bezier(0.22, 1, 0.36, 1)` on entry and `ease-in` on exit. Animate only opacity and a short vertical displacement within the expanding navigation region. Reduced-motion fallback: reveal or hide the complete region immediately.
- Link directional response. Job: confirm. Trigger: pointer hover or keyboard focus on a navigation link or persistent action. Duration: 150ms entering and 120ms leaving. Easing: `ease-out` on entry and `ease-in` on exit. Change underline thickness or move a small directional cue by no more than a few pixels. Reduced-motion fallback: apply the final underline, border, and cue state immediately.
- Header scrolled state. Job: orient. Trigger: leaving or returning to the document top. Duration: 0ms. Easing: none. Add or remove the divider without resizing the header. Reduced-motion fallback: identical immediate state change.

The shell has no primary narrative animation and no ambient animation. It must not animate the logo, loop any effect, smooth-scroll between destinations, or load a motion library. Only one direct-input response may run at a time.

## Accessibility

Use a skip link followed by one semantic `header`, one labeled primary `nav`, the page's single `main`, and one `footer` containing a separately labeled footer navigation. Do not place the main landmark inside the header or footer. Keep source order as skip link, header brand link, primary navigation, persistent action, main content, footer brand block, and footer navigation.

Use one navigation list shared across responsive presentations. Render destination controls as real links and the mobile disclosure control as a real button. Connect the button to the navigation region with `aria-controls` and expose its state with `aria-expanded`. Do not use ARIA menu roles for ordinary site navigation.

Keyboard users must be able to open the mobile navigation with Enter or Space, move through links in document order, close it with Escape, and retain a predictable focus location. Do not trap focus because the panel is not modal. Hidden collapsed content must not remain focusable.

Use `aria-current="page"` only for a link whose destination is the current page. State must use text weight, underline, border, icon shape, or programmatic attributes in addition to color. The toggle must use both visible text and a changing icon. Decorative arrow and menu geometry must be hidden from assistive technology.

No live-region announcement is needed for native navigation or the synchronous disclosure because their states are programmatically exposed. If a genuine asynchronous navigation state is introduced later, its destination plan must specify concise status and error announcements without unexpected focus movement.

Meet WCAG 2.2 AA contrast for all text, controls, selected markers, meaningful graphics, and focus indicators. Normal text requires at least 4.5:1, large text at least 3:1, and control boundaries and focus indicators at least 3:1 against adjacent colors. Verify blue separately on white and deep navy surfaces. Use a white or otherwise compliant footer focus treatment if the production blue fails there.

All targets must be at least 44 by 44 CSS pixels, with 48px to 56px targets for mobile primary actions. Support reflow at 320 CSS pixels and text enlargement to 200 percent without clipping, overlap, lost links, or horizontal page scrolling. The expanded mobile navigation may scroll vertically within the available viewport.

## Performance

Render the skip link, header brand, navigation labels, valid destinations, mobile fallback navigation, main landmark, footer promise, and footer links in the initial HTML. Navigation and page content must remain reachable before animation code, font files, or client-side application code completes.

Use the approved production wordmark as a compact SVG or correctly sized image with reserved dimensions. Do not redraw, distort, animate, or decorate it. Do not request a separate footer logo unless the operator supplies an approved reversed asset. Use plain text in the footer when that asset is unavailable.

Load only approved font weights used by the shell, preferably as self-hosted WOFF2 subsets with durable system fallbacks and non-blocking behavior. Reserve header and footer text space so font replacement does not move navigation or page content.

Implement disclosure and link responses with platform behavior and plain CSS plus the minimum script needed for enhancement, focus return, Escape handling, and scroll-state detection. Do not ship a motion library, icon library, WebGL, video, photography, map code, tracking interface, chatbot, or decorative animation for this scene. Footer content must not delay the first viewport, and header behavior must not depend on analytics or third-party requests.
